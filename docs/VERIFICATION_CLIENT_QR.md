# 查询客户端二维码接入验证

## 实现交付

- 查询客户端列表及 Key/接口说明增加“扫码接入”；新建或显式轮换后的 Key 弹窗可直接生成。
- 二维码为严格版本化 UTF-8 JSON：type/version/base_url/client_id/name/access_key，配置 URL 和专用查询 Key 一起传给扫码客户端，不放进 URL 查询参数。
- 本地内嵌 Nayuki v1.8.0 编码器，保留原 MIT 许可与上游文件摘要；不使用 CDN、在线二维码服务或远程渲染。
- 先验证 Key 是否属于当前选中的独立查询客户端，再生成二维码；源码只在浏览器临时 DOM/Canvas 中使用一次性或用户粘贴的 Key，不新增明文持久存储。
- 新增 `GET /api/v1/client/connection`，需要启用且至少有 read 或 sync 的 Client Key，不接受管理员 Cookie/Key、全局只读或 Source 凭据；只返回当前身份的 type/version/id/name/permissions。
- 已有 Key 不可回读，打开面板、验证、生成/下载都不轮换；未保存 Key 时只能明确确认重新生成，保留旧 Key 立即失效提示。
- 关闭/替换弹窗、修改输入、会话失效时清理旧图、输入值及 HTML value 属性，撤销临时对象 URL；迟到校验/下载回调不再展示或触发旧结果。
- 提供标准库 `examples/client_connection.py`：严格解析、目标服务身份验证、按 origin+ID 隔离的内存注册表，重复导入幂等，不同 Key 更新需明确确认。

完整使用说明和扫码协议见 `CLIENT_QR.md`。没有新增存储种类或数据库迁移；现有 PostgreSQL 实库验收仍待专用测试环境。

扫码专项覆盖：

- 中文、emoji、URL、客户端 ID 和完整 Key 从实际图像准确恢复；生成过程不改变客户端 revision。
- 同意提示与 URL 约束；二维码外部地址只编码、不由管理页面探测或发送 Key。
- 注册后查询真实公开资料，重复扫码不新增连接，不同 Key 更新须确认。
- PNG 下载实际解码；输入改变后旧图清除，关闭后对象 URL 撤销。
- 管理员、全局、来源、其他客户端 Key 拒绝，不因为验证失败退出管理员会话。
- 轮换后旧 Key 失效；Source 和其他查询身份不受影响。
- 仅 sync 可接入但目录请求仍为 403；撤权后验证和生成失败。
- 关闭、改变输入、会话失效后迟到响应不重建二维码；无效 JSON 不反显 Key。
- 桌面及 390px 手机视口的实际二维码解码，无页面级横向溢出、浏览器持久凭据、URL 密钥、外站请求或未捕获异常。

OpenCV 对 ECI 会输出兼容性警告；测试必须恢复与生成端一致的中文/emoji 和 Key，未忽略解码失败，也不宣称所有手机扫码 SDK 已认证。

## 复核与修正

- 只读复核提出 IDNA 规范化后数字主机校验绕过。主任务执行复现，确认全角 `０.０.０.０` 可变成通配地址、全角 `１２７.１` 可变成歧义数字主机；已改为 IDNA 后复核 IP/通配/数字拼写，并补全角、十六进制、IPv4-mapped 和正常全角 IPv4 的测试。
- 为避免 CSS 边框导致 Canvas 像素重采样，二维码 Canvas 使用无边框的整数模块尺寸与四模块白边。后续实际图像解码验证通过。
- 解析身份 JSON 的错误使用固定文本，不反显代理返回的原始正文或可能包含的 Key。
- 前端只读子任务因读取截断未完成全函数复核，不将该报告当作通过依据；相关边界以主任务代码核查及新增真实浏览器断言为证据。

## 本地真实服务核对

- 仍使用 `.local` profile、`.local/data` 文件工作区与 `127.0.0.1:8091`，未切换到其他工程或数据库。
- 本轮重建开发可执行文件；就绪检查通过，原管理员日志 `created=false`。
- 实际 HTML、JS、CSS、编码器脚本、OpenAPI 与管理 API 文档的字节摘要均和当前源码一致。
- 匿名 `/api/v1/client/connection` 返回 401。真实查询客户端的角色/权限及轮换验证在隔离环境执行，未读取真实密码或调用真实 Key 进行配对。
- 现有 5 条资料、5 个媒体资产、凭据摘要、内容游标、管理员及历史记录保持不变。
- 当前真实库有 0 个独立查询客户端；未为测试创建真实身份、生成/轮换真实 Key 或生成真实凭据二维码。
- 备份 `.local/backups/client-qr-20261025-195147/` 只复制当前工作区元数据并保留 ACL，未复制明文凭据文件或修改媒体。
- 未改变监听地址、开放防火墙或自动发现局域网地址。手机仍需配置实际可达地址和显式部署网络。
- 本轮启动的是前台本地进程，需保持运行终端开启，未安装系统常驻服务或开机任务。

## 能力边界

1. 本项目是资料数据服务，没有实际学习 App 的相机或连接管理源码。因此交付服务端二维码、协议及可运行导入模块；实际 App 需要把扫码器结果交给模块/同等实现，并接入 OS 安全凭据存储。
2. 普通系统相机可能仅显示 JSON，不能把“生成二维码”说成任何客户端都已支持自动添加；本轮没有修改其他项目或手机 App。
3. 二维码包含完整凭据，没有独立过期时间；用户主动下载/截图的副本需自行保护。设备间独立撤销应分别创建客户端。
4. 标准库注册示例仅在内存保存，不冒充已完成永久安全存储。验证默认 HTTPS，开发 HTTP 需明确允许，所有带 Key 请求不得把凭据带往重定向地址。
5. 未运行 PostgreSQL 实库或手机摄像头实机认证；软件图像解码、浏览器布局和真实本机 API 链路不能替代所有客户端平台验收。

机器报告位于 `.artifacts/client-qr-verification.json`、`.artifacts/client-qr-runtime.json`、Go/综合/浏览器验证报告；合成测试截图为 `client-qr-desktop.png` 和 `client-qr-mobile.png`，其中二维码不对应真实工作区。
