# 客户端反馈与推荐去重验收

## 交付范围

- 新增独立 `feedback` 权限；默认 read/sync、已有权限及 Key 不变，必须管理员显式勾选。
- 六类事件：recommended、impression、read、like、record、favorite。学习记录支持私有文本与 0–1 进度；状态类支持取消，推荐/曝光保留历史事实。
- 每批 1–100，Client ID 从实际 Bearer Key 推导，不允许请求指定其他身份。事务内再次验证 Key、启用及反馈授权。
- Client+event ID 幂等；相同 ID 改内容 409，整批失败回滚，重试不重复计数。独立反馈 sequence，不影响内容 /changes 游标。
- 状态按发生时间更新，同时间按接受序号；旧事件不覆盖较新状态。默认未给发生时间使用事务内服务器接收时间。
- 公开候选支持 exclude/recommended、seen、read、liked、recorded、favorited，unseen 简写、时间窗口及本页状态；排除在 limit/offset 前执行，按客户端隔离。
- 管理界面增加反馈统计/记录、按身份模拟候选及筛选，不替用户报告推荐/已读。
- QR v1 六字段保持不变，校验允许显式反馈能力，仍需 read 或 sync 才能作为查询连接配对。
- 标准库示例包括反馈 API、稳定事件 ID 构造与本地 SQLite 离线队列；队列不含 Key，成功完整回执后才删除；按 origin+Client ID 隔离。
- 新增 PostgreSQL 000004 迁移与反馈索引就绪检查，不改 000001–000003；文件库按需保存新记录，不自动回填或模拟历史行为。

使用说明见 `CLIENT_FEEDBACK.md`，接入模块为 `examples/feedback_client.py`。

## 本地部署与保留核验

- 使用原 `.local` profile、`.local/data` 与 `127.0.0.1:8091`，没有修改数据库选择或网络暴露。
- 经原有 restart-local 脚本重新构建，不使用 SkipBuild；原管理员 created=false。
- 当前服务 HTML/JS/CSS、OpenAPI、管理文档的字节摘要与源码一致，ready=200。
- 新反馈/事件接口匿名请求均为 401；真实 Key 功能在隔离服务验证，不读取真实凭据进行模拟上报。
- 原 5 条资料、5 个资产、全部记录、身份/账号/凭据摘要、来源、内容变更流及游标完整不变。

- 备份：`.local/backups/feedback-20261025-202659/`；复制工作区元数据并保留 ACL，未复制明文凭据或修改媒体。
- 前台服务需保持运行终端，未安装常驻系统服务或启动任务。

机器证据：`.artifacts/feedback-verification.json`、`feedback-runtime.json`、Go/综合/浏览器/二维码报告。反馈截图使用合成资料/笔记和临时服务，不是真实用户数据。

## 限制与未完成事项

- 没有真实学习 App 源码，未修改其他项目的学习按钮或相机界面；实际客户端须按协议把真实选择/曝光/动作接到上报模块。服务器查询本身不会自动伪造学习行为。
- 不增加服务端推荐算法，也不把所有查询返回的候选当作已推荐。
- 去重默认跨资料修订保留；时间窗口可用于冷却。状态筛选是动态集合，推荐轮次建议从 offset=0 开始；并发客户端没有预占或派单锁，不保证同时查询永不取得相同候选。
- 笔记/进度及离线队列是个人学习信息；实际 App 与部署者负责其存储权限、加密、隐私告知、删除/保留策略。不会自动删除原始历史事件。
- 专用 PostgreSQL 未提供，000004 与 SQL 筛选实库验证待执行；新增 `TestPostgresFeedbackFiltering` 将在 TEST_DATABASE_URL 配置的隔离 schema 中运行。不得以文件库或已编译代码替代实库通过结论。
