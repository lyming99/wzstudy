# 多客户端 Key 与权限配置验证记录

> 历史阶段记录：当前两链路身份与前端已继续改造，以 `VERIFICATION_TWO_CHAINS.md`、`CLIENT_ACCESS.md` 和最新 OpenAPI 为准。以下保留当时的测试证据，不代表当前全部实现。

验证日期：2026-10-25。范围为现有 Go 服务、内嵌管理端及兼容客户端 API；未读取或更改正式 `.local` 工作区、真实账号或客户端 Key。

## 实现范围

- 管理端「客户端管理」创建多个独立 Key，按客户端配置阅读、增量同步、资料入库、文件上传、接收推送五项权限。
- 客户端身份复用既有 manual 来源记录、ID 和 Key 格式，避免迁移资料归属与历史投递。
- 支持编辑权限、启停和单独轮换；Key 仅在创建/轮换显示，服务端只持久保存哈希。
- 阅读和同步接口分别鉴权；入库/上传在写事务内复查策略，上传在读取文件前预检；SSE 连接期间复查授权并在撤权后终止。
- 入库及收件箱校验自身来源 ID；客户端 Key 不能操作管理员 API。
- 推送目标只允许已启用且拥有 inbox 权限的客户端，广播同样过滤。
- 区分旧记录 null、显式空数组 []，防止重启或旧版更新请求意外恢复已撤销权限。

### Go 测试重点

- 五项权限逐一独立授权、全权限、显式零权限、旧记录默认策略。
- 仅 upload 不能绕过 ingest，通过大文件元数据写入资料。
- 客户端之间不能互相写入来源或读取对方收件箱，也不能提升为管理员。
- 未授权上传不在磁盘留下文件，阅读权限不能读取草稿。
- 同 Key 修改权限立即生效；启停、轮换、过期修订号、未知权限和重复权限处理。
- 已连接 SSE 对权限撤销、客户端停用、Key 轮换三种变化的响应。
- 文件重启恢复、空数组/旧 null 区别、内存事务回滚和权限切片隔离。
- 无 inbox 权限的客户端不能作为推送目标，广播不把它纳入接收端。

### 真实 Chrome 验证重点

运行于隔离临时文件工作区，使用随机测试凭据及系统 Chrome（本次完整回归版本 156.0.8078.47），未调用外部网页。

- 在管理端创建学习端与采集端，各自 Key 不同，分别只获得选定能力。
- 管理端修改权限而不轮换 Key；全部取消后所有受管操作被拒绝，启停不恢复权限。
- 原 Key 轮换后立即失效，其他客户端不受影响。
- 恶意 HTML 描述只作为文字显示；Key 不进入列表、浏览器存储或持久文件明文。
- 服务进程重启后，客户端、哈希和权限恢复。
- 手机端侧栏收起后不遮挡页面，统计区域不被挤压；权限弹窗可在窄屏使用。
- 客户端状态明确为「已启用 / 已停用」，不再复用资料发布状态的文案。
- 原管理端文章、音视频、轮播、审核、搜索、分页、专题、即时/定时推送、RSS 安全拒绝、CSV 导出、会话与持久化均通过完整回归。

## 未验证及边界

- 未连接 PostgreSQL 专用测试数据库，不把文件/内存存储通过视为 PostgreSQL 实机验证。来源采用原 JSONB 存储契约扩展字段，不新增或改写迁移。
- 未部署生产、未替换 dist 发行包、未重启任何既有正式工作区服务。测试二进制仅生成在 `.artifacts`。
- read/sync 访问整个工作空间的已发布内容，不支持按来源、分类或标签隔离阅读，不等于多租户权限。
- READ_API_KEY 保留为旧版全局只读兼容凭据，不受单个客户端启停控制；新客户端不需要分发它。
- 文件存储仍是单进程模式，未新增多实例文件存储支持或系统级通知能力。

管理端使用方法及迁移说明见同目录 `CLIENT_ACCESS.md`。
